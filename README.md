# Trace · PCB Inspection Studio

Trace is a static educational dashboard for comparing PCB images against a clean reference. It runs a browser-side pixel difference check and draws boxes around regions that changed.

## Try the built-in fault demo

Open the site and choose **Run sample fault test**. It compares `samples/clean-reference.svg` with `samples/fault-open-trace.svg`; the open trace should appear as a highlighted difference region.

## Compare your own images

1. Choose **Set clean reference** and upload a known-good board image.
2. Choose **Upload test image** and select the inspection image.
3. Keep the board in the same orientation, scale, crop, and lighting as the reference.
4. Export the visual comparison report if needed.

The demo uses a simple pixel threshold and connected regions. It highlights visual differences; it does not parse Gerber files, classify electrical faults, or prove a board is defective. Changes in camera position, lighting, focus, or board alignment can cause false positives or hide small changes.

## Generated Gerber test files

`samples/manufacturing/` contains three ZIP packages with copper, solder mask, silkscreen, outline, drill, and notes:

- `trace-status-clean.zip` — clean 42 × 30 mm single-sided LED status board.
- `trace-status-open-trace.zip` — intentional 3 mm break in the series path.
- `trace-status-copper-short.zip` — intentional copper bridge between +5 V and GND.

These are genuine RS-274X Gerber-format and Excellon drill test artworks generated by `samples/generate_test_gerbers.py`. They are educational examples, not a validated manufacturing release. Do not fabricate the faulted packages; inspect every layer and run your manufacturer's DFM checks before ordering.

## Files

- `index.html` — dashboard structure
- `styles.css` — visual design and responsive layout
- `app.js` — image comparison, overlays, and report export
- `assets/` — interface illustrations
- `samples/` — comparison previews and generated Gerber packages
- `manifest.json` — app metadata
- GitHub Pages serves the site directly from the `main` branch root

Open `index.html` or serve this folder using any static web server. No build step is required.
